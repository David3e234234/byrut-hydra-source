# ByrutGame → Hydra Launcher source

Скрипт собирает раздачи с `byrutgame.org` и генерирует **byrut.json** — источник загрузок для [Hydra Launcher](https://github.com/hydralauncher/hydra) (формат: `{ name, downloads: [{ title, uris, uploadDate, fileSize }] }`).

Magnet-ссылки строятся из скачанных `.torrent`-файлов (infohash v1), поэтому всё работает напрямую в Hydra.

## Облачные раздачи (с 2026-09-18)

У части игр вместо торрента (или вместе с ним) есть «Альтернативные раздачи» — файловое хранилище со прямыми ссылками (Pixeldrain, Gofile, MediaFire, Buzzheavier, MixDrop и др.). Скрипт подгружает их через AJAX-эндпоинт сайта и добавляет в `uris` те, что Hydra умеет качать напрямую (pixeldrain, gofile, mediafire, datanodes, fuckingfast, vikingfile, rootz). Ссылки на неподдерживаемые хостеры (buzzheavier, mixdrop, workupload, mega, 1fichier и пр.) отбрасываются — иначе Hydra отфильтровал бы релиз целиком. Игра «только облако» тоже попадает в JSON — с облачными ссылками вместо magnet.

## Файлы

| Файл | Назначение |
|---|---|
| `scrape.mjs` | скрапер: обходит страницы сайта, скачивает `.torrent`, строит magnet и пишет `byrut.json` |
| `byrut.json` | итоговый источник для Hydra |
| `.cache/downloads.json` | кэш «страница игры → magnet»: повторные запуски не качают торренты заново |
| `.github/workflows/update.yml` | автозапуск по расписанию + коммит обновлённого JSON |

## Запуск

```bash
node scrape.mjs --pages 3          # последние 3 страницы новостей (~120 свежих игр, по умолчанию)
node scrape.mjs --pages 10         # 10 страниц новостей
node scrape.mjs --full             # перечитать всё и обновить даты/размеры у кэшированных
node scrape.mjs --all              # ВЕСЬ сайт через sitemap (~55 000 игр, см. ниже)
node scrape.mjs --all --limit 1000 # первые 1000 игр из sitemap (порциями)
```

### Покрытие сайта

| Режим | Что парсит | Время |
|---|---|---|
| по умолчанию (`--pages 3`) | только новости: ~3 последние страницы (~120 игр) | минуты |
| `--pages N` | N страниц новостей | N × ~2,5 сек × игры |
| `--all` | весь каталог: ~55 500 страниц игр из sitemap | **несколько дней** (паузы вежливости) |
| `--all --limit N` | до N **новых** игр за запуск | ~3,5 ч на 2500 в Actions |
| `--check-updates --updates-limit N --refresh` | проверяет N закэшированных игр на обновление версии на сайте | ~1,25 ч на 1500 |

`--all` идёт по sitemap'ам (`news_pages.xml` + `news_pages2.xml`), кэш сохраняется каждые 50 игр, так что процесс можно прерывать и продолжать. Порядок обхода — как в sitemap (от новых к старым), поэтому даже частичный прогон сначала наполняет каталог свежим.

**Режим `--check-updates`** решает проблему устаревших magnet'ов: у каждой игры в кэше хранится отпечаток «размер + дата обновления + название». Если на сайте вышла новая версия репака (изменился размер/дата), скрипт замечает это, перекачивает `.torrent` и перезаписывает magnet. `--refresh` разрешает перекачку, без него изменения только фиксируются в метаданных. В Actions запускается ежедневно по 1500 игр — полный круг по каталогу примерно раз в 5 недель.

**Для сервера/GitHub Actions:** полный `--all` не уложить в лимиты Actions (6 ч на job). Варианты: крутить `--all --limit K` по N игр за запуск (кэш накапливается между запусками), либо гонять на своей машине/VPS за один долгий прогон.

Требуется Node.js 18+. Скорость ограничена паузами (`PAGE_DELAY_MS` / `TORRENT_DELAY_MS` в начале `scrape.mjs`), чтобы не нагружать сайт.

## Как подключить в Hydra

Вариант А — через GitHub (рекомендуется):

1. Создайте репозиторий и запушьте эти файлы.
2. Включите GitHub Actions (вкладка Actions → включить workflows) — JSON будет обновляться сам по расписанию.
3. Ссылка на источник: `https://raw.githubusercontent.com/<user>/<repo>/main/byrut.json`
4. Hydra → **Настройки → Источники загрузки → +** → вставить ссылку.

Вариант Б — локально: держите `byrut.json` на диске и обновляйте скриптом, но в актуальной версии Hydra добавить источник можно только по публичной URL-ссылке (локальный импорт — в открытом PR [#2632](https://github.com/hydralauncher/hydra/pull/2632)).

## Как работает автообновление

`update.yml` запускается один раз в день по cron в 03:00 UTC и по кнопке (workflow_dispatch). Три фазы выполняются последовательно отдельными job, у каждого свой лимит времени. После каждой фазы результаты сразу публикуются скриптом `publish.sh` (коммит + пуш с защитой от гонок: если remote ушёл вперёд — rebase и повтор до 6 раз; при конфликте данных побеждает свежий скрап).

1. `node scrape.mjs --pages 5` + публикация — новинки, timeout 30 мин
2. `node scrape.mjs --all --limit 2500` + публикация — порция каталога, timeout 300 мин
3. `node scrape.mjs --check-updates --updates-limit 1500 --refresh` + публикация — проверка версий, timeout 180 мин
4. Ссылка `raw.githubusercontent.com/.../byrut.json` всегда отдаёт свежую версию; Hydra подтянет её через «Синхронизировать» в настройках источников.

Публикация после каждой завершившейся фазы означает: если следующая job упадёт или упрётся в timeout, результаты предыдущих фаз уже останутся в `main`.

## Заметки

- Игры, у которых нет ни торрента, ни облачного хранилища (анонсы без релиза), пропускаются.
- В режиме по умолчанию покрываются только новинки; для всего каталога используйте `--all` (см. таблицу выше).
- `dn=` в magnet берётся из заголовка страницы; сопоставление в Hydra идёт по названию (`title`), так что чистота заголовка важнее.
- Первое полное заполнение кэша (несколько страниц) может занять несколько минут из-за пауз.
